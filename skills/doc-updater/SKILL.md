# Doc Updater

코드 변경사항을 분석하여 프로젝트 문서(마크다운)와 이슈 트래커를 자동으로 업데이트하는 스킬.

**핵심 원칙:** 변경사항 분석 → 업데이트 대상 식별 → 변경안 제안 → 승인 후 적용

## 업데이트 프로세스

### 1단계: 변경사항 분석

스킬 호출 시 현재 코드 변경사항을 수집한다.

**수집 대상:**

```
git diff HEAD (스테이징 + 언스테이징 변경사항)
git log --oneline -10 (최근 커밋 히스토리)
git diff main...HEAD (브랜치 전체 변경사항, 브랜치 작업 시)
```

**분석 항목:**
- 변경/추가/삭제된 파일 목록
- 변경의 성격 (신규 기능, 버그 수정, 리팩토링, 설정 변경 등)
- 공개 API 변경 여부
- 의존성 변경 여부
- 설정/환경 변경 여부

### 2단계: 업데이트 대상 식별

변경사항을 바탕으로 업데이트가 필요한 문서와 이슈를 찾는다.

**프로젝트 문서 스캔:**

```
프로젝트 내 모든 *.md 파일을 검색하여 목록화한다.
각 문서의 내용을 읽고 코드 변경사항과의 관련성을 판단한다.
```

**문서-변경 매핑 기준:**

| 변경 유형 | 업데이트 대상 문서 |
|---|---|
| 신규 기능 추가 | README.md, CHANGELOG.md, 해당 기능 문서 |
| 공개 API 변경 | API 문서, README 사용법 섹션 |
| 설치/설정 변경 | README.md 설치 가이드, 환경 설정 문서 |
| 의존성 변경 | README.md, 설치 가이드 |
| 프로젝트 규칙 변경 | CLAUDE.md |
| 버그 수정 | CHANGELOG.md |
| 리팩토링 | 아키텍처 문서 (구조 변경 시만) |
| 테스트 변경 | 테스트 가이드 (있는 경우만) |

**이슈 트래커 확인:**

MCP로 연결된 이슈 트래커가 있는 경우:
- 현재 브랜치명/커밋 메시지에서 이슈 번호 추출
- 해당 이슈의 현재 상태 확인
- 관련 이슈 목록 파악

### 3단계: 변경안 제안

식별된 각 대상에 대해 구체적인 변경안을 사용자에게 제시한다.

**제안 형식:**

```
## 문서 업데이트 제안

### 1. [파일경로]
- 변경 이유: [왜 업데이트가 필요한지]
- 변경 내용 요약: [무엇을 변경할지]
- 변경 상세:
  [구체적인 추가/수정/삭제 내용]

### 2. [이슈 트래커 - 이슈 #번호]
- 이슈 설명 업데이트: [변경 내용]
- 댓글 추가: [작업 계획 또는 진행 상황]
- 상태/완료율 변경: [변경 내용]
```

**제안 시 주의사항:**
- 변경이 불필요한 문서는 제안하지 않는다
- 각 변경안은 구체적이고 실행 가능해야 한다
- 사용자가 선택적으로 승인/거부할 수 있도록 항목별로 분리한다

### 4단계: 승인 및 적용

```
AskUserQuestion 도구 사용:
  question: "문서 업데이트 제안을 검토해주세요. 어떻게 진행할까요?"
  options:
    - label: "전체 승인"
      description: "모든 제안을 적용합니다"
    - label: "선택 적용"
      description: "적용할 항목을 선택합니다"
    - label: "수정 필요"
      description: "제안을 수정한 후 다시 검토합니다"
```

**적용 순서:**
1. 프로젝트 마크다운 문서 수정
2. 이슈 트래커 업데이트 — 아래 항목을 **모두** 수행:
   - 댓글 추가 (구현 내역/진행 상황)
   - 완료율(done_ratio) 업데이트
   - **이슈 상태 변경** (필수 — 구현 완료 시 `해결`, 작업 중이면 `진행` 등)

## 이슈 트래커 연동 규칙

### 문서 분리 원칙

| 위치 | 내용 | 용도 |
|---|---|---|
| **이슈 설명** | "무엇을" 할지 | 요구사항, 버그 현상, 수정 범위 |
| **댓글 — 계획** | "어떻게" 할지 | 구현 단계, 기술 접근법, 파일 목록 |
| **댓글 — 진행** | 작업 결과 | 완료 항목, 변경 요약, 남은 작업 |
| **상태/완료율** | 진행도 | 상태 변경, done_ratio 업데이트 |

### 댓글 작성 규칙

**작업 계획 댓글:**

```markdown
## 작업 계획

### 접근 방식
[기술적 접근법 설명]

### 수정 대상 파일
- `파일경로` — [변경 내용]

### 작업 단계
1. [단계 1]
2. [단계 2]

### 예상 영향
[영향받는 기능/코드]
```

**진행 상황 댓글:**

```markdown
## 진행 상황 업데이트

### 완료된 작업
- [x] [완료 항목]
- [x] [완료 항목]

### 변경 요약
- `파일경로` — [변경 내용 요약]

### 남은 작업
- [ ] [미완료 항목]

### 비고
[추가 참고사항]
```

### 이슈 번호 추출

다음 패턴에서 이슈 번호를 자동 추출한다:
- 브랜치명: `feature/123-description`, `fix/456`, `issue-789`
- 커밋 메시지: `#123`, `refs #123`, `fixes #123`, `closes #123`
- 사용자가 직접 지정한 이슈 번호

## 프로젝트 문서 업데이트 규칙

### CHANGELOG.md

Semantic Versioning과 Keep a Changelog 형식을 따른다:

```markdown
## [Unreleased]

### Added
- 새로운 기능 설명

### Changed
- 변경된 기능 설명

### Fixed
- 수정된 버그 설명
```

**기존 CHANGELOG가 없는 경우:** 프로젝트의 기존 형식을 존중하거나, 사용자에게 형식을 확인한다.

### README.md

변경이 다음에 해당할 때만 업데이트:
- 설치 방법 변경
- 사용법 변경
- 새로운 주요 기능 추가
- 의존성 변경
- 환경 설정 변경

기존 README 구조와 스타일을 유지한다.

### CLAUDE.md

프로젝트 규칙이나 컨벤션이 변경되었을 때만 업데이트한다. 기존 구조를 유지하며 해당 섹션만 수정한다.

### 기타 문서

`docs/` 하위 문서는 해당 기능과 직접 관련된 내용이 변경되었을 때만 업데이트한다.

## 주의사항

**반드시:**
- 변경사항을 먼저 분석한 후 업데이트 대상을 결정
- 항목별로 분리하여 제안 (사용자가 선택 가능)
- 기존 문서의 스타일과 형식을 유지
- 이슈 트래커 댓글은 Markdown 형식 사용
- 승인 후에만 실제 변경 적용

**금지:**
- 분석 없이 일괄 업데이트
- 사용자 승인 없이 문서 수정
- 관련 없는 문서 수정 제안
- 이슈 설명과 작업 계획을 혼합 작성
- 기존 문서 형식을 임의로 변경

## 워크플로우 예시

```
유저: /doc-updater

Claude: doc-updater 스킬을 실행합니다.

[1단계: 변경사항 분석]
Claude: 현재 변경사항을 분석합니다.
  - git diff 분석
  - 최근 커밋 확인
  - 변경 성격: 신규 기능 추가 (JWT 인증)

[2단계: 업데이트 대상 식별]
Claude: 프로젝트 문서와 이슈 트래커를 스캔합니다.
  - 마크다운 문서: README.md, docs/auth.md, CHANGELOG.md
  - 이슈 트래커: #42 (JWT 인증 구현)

[3단계: 변경안 제안]
Claude:
  ## 문서 업데이트 제안

  ### 1. README.md
  - 변경 이유: 인증 방식이 세션에서 JWT로 변경됨
  - 변경 내용: 설치 가이드에 JWT_SECRET 환경변수 추가

  ### 2. CHANGELOG.md
  - 변경 이유: 새 기능 추가 기록
  - 변경 내용: [Unreleased] > Added 섹션에 JWT 인증 항목 추가

  ### 3. docs/auth.md
  - 변경 이유: 인증 문서 전면 업데이트 필요
  - 변경 내용: JWT 토큰 발급/검증 흐름, API 사용법

  ### 4. 이슈 #42
  - 댓글: 작업 진행 상황 업데이트
  - 완료율: 80% → 100%
  - 상태: 진행중 → 해결됨

[4단계: 승인]
유저: 전체 승인

Claude: 승인된 변경사항을 적용합니다.
  ✓ README.md 업데이트 완료
  ✓ CHANGELOG.md 업데이트 완료
  ✓ docs/auth.md 업데이트 완료
  ✓ 이슈 #42 댓글 추가 및 상태 변경 완료
```
